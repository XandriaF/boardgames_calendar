# Как запустить сайт «Настолки билайн» — по шагам, максимально подробно

Ничего заранее уметь не нужно. Просто идите по порядку сверху вниз, ничего не пропуская.

Всего будет 4 шага:

1. Заводим Google-таблицу и вставляем в неё «мозги» сайта (Apps Script).
2. Получаем от Google специальную ссылку.
3. Вписываем эту ссылку в один файл сайта.
4. Выкладываем сайт на Netlify — получаем адрес, который можно всем разослать.

На всё — минут 20, если не отвлекаться.

---

## Шаг 1. Google-таблица

**1.1.** Откройте [sheets.google.com](https://sheets.google.com) под тем Google-аккаунтом, под которым удобно вести таблицу (можно личный, можно рабочий — это не принципиально, но потом с этого же аккаунта нужно будет ставить скрипт).

**1.2.** Нажмите **Пустой файл** (большой плюс / blank spreadsheet) — создастся новая пустая таблица.

**1.3.** Переименуйте её: кликните на «Новая таблица» в левом верхнем углу и впишите, например, «Настолки билайн».

**1.4.** Теперь занесём туда готовую структуру данных, которую я подготовил (файл `Настолки_Билайн_данные.xlsx`):

- В верхнем меню: **Файл → Импорт**.
- Откроется окно. Перейдите на вкладку **Загрузка** и перетащите туда файл `Настолки_Билайн_данные.xlsx` (или нажмите «Выбрать файл на устройстве» и найдите его).
- После загрузки Google спросит, **что делать с импортируемыми данными**. Здесь важно выбрать вариант **«Вставить новые листы»** (Insert new sheet(s)) — НЕ «Заменить таблицу» и НЕ «Заменить текущий лист».
- Нажмите **Импортировать данные**.

**1.5.** Теперь внизу экрана, на вкладках-«ярлычках» листов, у вас должно появиться три новых листа: **Инструкция**, **Мероприятия**, **Записи** — вдобавок к пустому «Лист1», который Google создал по умолчанию. Пустой «Лист1» можно смело удалить (правой кнопкой по ярлычку → «Удалить») — он не нужен.

**1.6.** Откройте лист **Мероприятия** и посмотрите на данные — туда уже перенесены игры из вашего старого календаря. Город у всех стоит «Москва» по умолчанию (в старом календаре города не было) — если часть игр в других городах, поправьте вручную прямо в ячейках. Колонка **D** называется «Жанр» (например «Евро», «Пати», «Кооператив», «НРИ») — тоже необязательная, можно оставить пустой. Колонки **K–P** (Сложность, Макс. время игры, Тесера, BGG, Сеттинг, Картинка) — тоже необязательные, заполняются только если хотите показать эту информацию на сайте.

**1.7.** Лист **Записи** не трогайте — туда сайт будет сам записывать, кто на что записался. Руками там ничего заполнять не нужно.

**1.8.** Последняя мелочь, но важная: проверьте часовой пояс таблицы, чтобы даты новых игр не съезжали на день. **Файл → Настройки таблицы** (Settings) → вкладка **Общие** → **Часовой пояс** → должно быть выбрано что-то вроде «(GMT+03:00) Москва». Если нет — выберите московский пояс и нажмите **Сохранить настройки**.

Таблица готова. Теперь вставим в неё скрипт, который умеет отдавать данные сайту и записывать в неё новых участников.

## Шаг 2. Apps Script — «мозги» сайта

Это встроенный в Google Таблицы редактор кода. Пугаться не нужно — просто скопируем готовый код целиком, ничего писать самим не придётся.

**2.1.** В вашей Google-таблице, в верхнем меню: **Расширения (Extensions) → Apps Script**.

**2.2.** Откроется новая вкладка браузера — это редактор кода (script.google.com). Там уже будет файл с названием `Код.gs` или `Code.gs` и внутри — заготовка вида:

```
function myFunction() {

}
```

**2.3.** Кликните внутрь этого окна с кодом, нажмите **Ctrl+A** (выделить всё), затем **Delete** — весь текст должен исчезнуть.

**2.4.** Откройте на своём компьютере файл `Code.gs` из папки с сайтом (можно в Блокноте / любом текстовом редакторе), выделите там всё (**Ctrl+A**), скопируйте (**Ctrl+C**).

**2.5.** Вернитесь в окно Apps Script и вставьте (**Ctrl+V**) — весь код должен появиться в редакторе.

**2.6.** Сохраните: нажмите на иконку дискеты в панели инструментов (или **Ctrl+S**).

**2.7.** Теперь опубликуем это как веб-приложение, чтобы сайт мог с ним общаться:

- Справа сверху — синяя кнопка **Развернуть (Deploy)** → **Новое развёртывание (New deployment)**.
- Рядом с полем «Выберите тип» (Select type) нажмите на иконку ⚙️ (шестерёнку) → выберите **Веб-приложение (Web app)**.
- Появятся поля:
  - **Описание** — можно вписать что угодно, например «настолки билайн», необязательно.
  - **Execute as / Выполнять как** — должно стоять **Я (Me)**.
  - **Who has access / У кого есть доступ** — выберите **Все (Anyone)**. Это нужно, чтобы сайт (который открыт всем) мог получать данные. Если ИБ компании не разрешает вариант «Все» — выберите «Все в организации» (Anyone within [ваша организация]), тогда сайт будет работать только для тех, кто залогинен в корпоративный Google.
- Нажмите **Развернуть (Deploy)**.

**2.8.** Google попросит авторизовать доступ — это нормально, ведь скрипт сейчас будет читать и писать в вашу же таблицу:

- Нажмите **Авторизовать доступ (Authorize access)**.
- Выберите свой Google-аккаунт.
- Может появиться экран **«Google не подтвердил это приложение»** («Google hasn't verified this app») — это нормально и ожидаемо, ведь это ваш собственный только что написанный скрипт, а не чужое приложение. Нажмите мелкую ссылку **Дополнительные настройки (Advanced)** внизу, затем **Перейти на страницу «[название проекта]» (небезопасно)**.
- На следующем экране нажмите **Разрешить (Allow)**.

**2.9.** После этого появится окошко с надписью **«Развёртывание обновлено»** и полем **URL веб-приложения (Web app URL)** — это ссылка вида:

```
https://script.google.com/macros/s/AKfycb.........................../exec
```

Скопируйте её целиком (рядом есть кнопка-иконка «копировать») и сохраните куда-нибудь рядом — она понадобится буквально через минуту. Нажмите **Готово (Done)**.

⚠️ **Важно на будущее:** если вы потом захотите поменять код `Code.gs` (например, что-то в логике), одного сохранения недостаточно — нужно **создать новое развёртывание** (или зайти в «Управление развёртываниями» → нажать на карандаш/редактировать у существующего → в поле «Версия» выбрать «Новая версия» → Развернуть). Иначе изменения не попадут на уже опубликованный URL, и сайт продолжит работать по-старому.

**2.10.** Закройте вкладку с редактором кода и вернитесь к вашей Google-таблице, затем **обновите страницу браузера** (F5). Через пару секунд должно произойти две вещи:

- вверху появится новое меню **«Настолки»** (рядом с «Файл», «Правка» и т.д.);
- автоматически появится (или обновится) лист **«Календарь»** — это тот самый понедельный календарь с цветными ячейками, как в вашем исходном файле, только теперь он собирается сам из листа «Мероприятия» и не может разойтись с сайтом. Пустые дни остаются просто белыми — сразу видно, где в расписании пробел.

Если после обновления страницы Google спросит разрешение ещё раз (это отдельный, более простой запрос, не такой как в 2.8) — нажмите «Разрешить». Дальше календарь будет обновляться сам каждый раз, когда вы открываете таблицу, а если нужно обновить прямо сейчас, не переоткрывая — жмите **Настолки → Обновить календарь**.

## Шаг 3. Вписываем ссылку в сайт

**3.1.** В папке с сайтом найдите файл `config.js`, откройте его в любом текстовом редакторе (Блокнот подойдёт).

**3.2.** Там будет строка вида:

```js
window.APP_CONFIG = {
  APPS_SCRIPT_URL: "ВСТАВЬТЕ_СЮДА_URL_ВЕБ_ПРИЛОЖЕНИЯ"
};
```

**3.3.** Замените текст `ВСТАВЬТЕ_СЮДА_URL_ВЕБ_ПРИЛОЖЕНИЯ` (вместе с кавычками вокруг него — кавычки оставьте, текст внутри замените) на ту ссылку, которую скопировали в шаге 2.9. Должно получиться примерно так:

```js
window.APP_CONFIG = {
  APPS_SCRIPT_URL: "https://script.google.com/macros/s/AKfycb.........................../exec"
};
```

**3.4.** Сохраните файл (**Ctrl+S**), не меняя ни название файла, ни расширение `.js`.

## Шаг 4. Netlify — выкладываем сайт в интернет

Два способа. **Способ А** быстрее для первого раза, но иногда капризничает с перетаскиванием
папки (браузер может не прочитать какой-то файл — про это ниже). **Способ Б** через GitHub
чуть дольше настроить один раз, зато потом обновлять сайт — одно нажатие, без перетаскиваний,
и он не ломается на ровном месте.

### Способ А. Перетащить папку (быстро)

**4.1.** Откройте [netlify.com](https://www.netlify.com) и нажмите **Sign up** (или **Log in**, если уже есть аккаунт). Можно зарегистрироваться через Google/GitHub-аккаунт — так быстрее.

**4.2.** После входа вы попадёте на главную панель (дашборд). Найдите кнопку **Add new site** (обычно справа сверху) → в выпадающем списке выберите **Deploy manually**.

**4.3.** Откроется страница с большой пунктирной областью и надписью типа «Drag and drop your site output folder here». Откройте у себя на компьютере папку с сайтом (ту, где лежат `index.html`, `styles.css`, `app.js`, `config.js`, `organizer.html`, `organizer.js`, `netlify.toml`) — и перетащите **саму папку целиком** (не отдельные файлы по одному, а всю папку сразу) в эту область браузера.

⚠️ **Если видите ошибку «Unable to read file ...» (например, про `config.js`)** — почти всегда это значит, что папка лежит в облачной синхронизации (OneDrive / Google Диск / Яндекс Диск) и файл физически не скачан на компьютер, а хранится «только в облаке». Что попробовать:

- Правой кнопкой по папке с сайтом → пункт вроде **«Всегда хранить на этом устройстве»** (OneDrive) или аналог для вашего облачного сервиса → подождать, пока файлы скачаются полностью → попробовать перетащить снова.
- Или скопировать всю папку на Рабочий стол (обычно вне облачной синхронизации) и перетаскивать уже её.
- Или просто перейти к **Способу Б** ниже — он этой проблемы не знает вообще.

**4.4.** Подождите несколько секунд — Netlify загрузит файлы и опубликует сайт. Появится адрес вида:

```
https://random-name-123456.netlify.app
```

Нажмите на эту ссылку — должен открыться ваш сайт с анонсами игр.

**4.5.** (Необязательно, но приятно) Можно сделать адрес более осмысленным: **Site settings → Change site name** → впишите, например, `beeline-nastolki` → адрес станет `https://beeline-nastolki.netlify.app`. Также в настройках можно подключить свой корпоративный домен, если он есть.

**Готово — сайт опубликован.** Эту ссылку и можно рассылать коллегам.

### Способ Б. Через GitHub (надёжнее, удобнее обновлять потом)

**Часть 1 — загружаем файлы на GitHub**

**4.1.** Откройте [github.com](https://github.com) → **Sign up** (если аккаунта нет) или **Sign in**.

**4.2.** В правом верхнем углу нажмите **+** → **New repository**.

**4.3.** Заполните форму:
- **Repository name** — впишите, например, `nastolki-bilain`.
- Оставьте **Private** (по умолчанию) — необязательно, но так безопаснее.
- Поставьте галочку **Add a README file** — так проще будет заливать файлы дальше.
- Нажмите зелёную кнопку **Create repository**.

**4.4.** На странице репозитория нажмите кнопку **Add file** (справа над списком файлов) → **Upload files**.

**4.5.** Откройте на компьютере папку с сайтом, выделите там **все файлы** (кликните на первый файл, потом Ctrl+A) и перетащите это выделение в область на странице GitHub с надписью «Drag files here to add them to your repository». Либо нажмите ссылку **choose your files** и выберите все файлы через диалоговое окно.

**4.6.** Внизу страницы — поле для сообщения о коммите, оставьте как есть или впишите «Первая версия сайта», нажмите зелёную кнопку **Commit changes**.

**4.7.** Убедитесь, что файлы (`index.html`, `styles.css`, `app.js`, `config.js` и остальные) появились в списке файлов репозитория.

**Часть 2 — подключаем Netlify к этому репозиторию**

**4.8.** В Netlify: **Add new site** → в этот раз выберите **Import an existing project** (не «Deploy manually»).

**4.9.** Нажмите **Deploy with GitHub**. Появится окно авторизации GitHub — разрешите Netlify доступ (можно выбрать «только этот репозиторий» в списке).

**4.10.** В списке репозиториев найдите и выберите `nastolki-bilain`.

**4.11.** На экране настроек деплоя:
- **Build command** — оставьте пустым (сотрите, если там что-то есть).
- **Publish directory** — впишите одну точку: `.`
- Нажмите **Deploy** (может называться «Deploy site» / «Deploy nastolki-bilain»).

**4.12.** Через несколько секунд сайт опубликуется по адресу вида `https://random-name.netlify.app` — так же, как в Способе А (шаги 4.4–4.5 про адрес и переименование применимы точно так же).

**Как обновлять сайт дальше (в этом способе — без перетаскиваний в Netlify вообще):**
Откройте нужный файл прямо на GitHub (кликните на его название в репозитории) → нажмите иконку карандаша (**Edit**) справа сверху → внесите правки → внизу **Commit changes**. Netlify сам заметит изменение и выкатит новую версию сайта в течение минуты-двух — обновлять ничего в Netlify руками не нужно.

## Как дальше жить с этим (частые задачи)

### Добавить новую игру

Два способа — оба рабочие, выбирайте удобный:

- **Через сайт (проще):** откройте ссылку «для организаторов» внизу главной страницы сайта (`ваш-сайт.netlify.app/organizer.html`), заполните форму (включая необязательные поля «Сложность», «Макс. время игры», «Сеттинг», ссылку на картинку, ссылки на Тесеру/BGG) — игра сама появится и на сайте, и в таблице, а внизу вы сразу получите готовый текст для поста в чат.
- **Прямо в таблице:** откройте лист «Мероприятия» и впишите новую строку руками, по порядку колонок A–P: дата, время, город, жанр, игра, место, организатор, макс. участников, статус (из выпадающего списка выберите «Набор открыт»), комментарий, сложность, макс. время игры (мин), ссылка на Тесеру, ссылка на BGG, сеттинг (ключевые слова через запятую), ссылка на картинку. Последние 8 колонок (жанр и всё после комментария) необязательные — можно оставлять пустыми. Сайт подхватит новую строку при следующей загрузке страницы.

### Ссылка на картинку — откуда её взять

В поле «Картинка» нужна именно прямая ссылка на само изображение (не на страницу сайта, где оно показано). Проще всего:

- Загрузить картинку в Google Диск → правой кнопкой → **Открыть доступ** → «Все, у кого есть ссылка» → скопировать ссылку. Подойдёт и любой другой хостинг картинок (Imgur и т.п.).
- Скопировать ссылку на обложку игры со страницы Tesera или BGG (правой кнопкой по картинке → «Копировать адрес картинки»).

Если ссылка окажется битой или недоступной — карточка на сайте просто не покажет картинку (без ошибок и без «битых» иконок), остальная информация отобразится как обычно.

### Поменять код Code.gs (если попросите меня что-то доработать в логике)

1. Откройте вашу Google-таблицу → **Расширения → Apps Script** (это тот же адрес, что открывался в шаге 2 — можно добавить в закладки браузера, чтобы каждый раз не искать через меню).
2. Вставьте новый код вместо старого, сохраните (**Ctrl+S**).
3. **Обязательно**: **Развернуть → Управление развёртываниями** → у существующего развёртывания нажмите на иконку карандаша → в поле «Версия» выберите **Новая версия** → **Развернуть**.
4. URL веб-приложения при этом остаётся тем же самым — в `config.js` ничего менять не нужно.

### Поменять что-то на самом сайте (текст, цвета, дизайн)

Если сайт выложен **Способом А** (перетаскиванием):
1. Отредактируйте нужный файл (`index.html`, `styles.css`, `app.js`, ...) у себя на компьютере.
2. Зайдите в Netlify → откройте ваш сайт → вкладка **Deploys**.
3. Перетащите обновлённую папку целиком в область **«Drag and drop your site output folder here»** на этой же странице — Netlify выкатит новую версию по тому же адресу.

Если сайт выложен **Способом Б** (через GitHub):
1. Откройте файл в репозитории на GitHub → иконка карандаша (**Edit**) → внесите правки → **Commit changes**.
2. Ничего больше делать не нужно — Netlify сам подхватит изменение за минуту-две.

### Лист «Календарь» — визуальный вид на 16 недель вперёд

Это тот же понедельный календарь с цветными ячейками, к которому вы привыкли, только теперь
он **не редактируется руками** — он пересобирается автоматически из листа «Мероприятия»
и всегда показывает 16 недель вперёд, начиная с текущей недели.

Цвет ячейки = статус игры (тот же цвет, что был в вашем старом файле, легенда — в самом
верху листа «Календарь»):

- жёлтый — «Набор открыт»
- зелёный — «Набрано»
- красный — «Отменено»
- синий — «Непубличное»
- голубой — «Черновик»

**Пустой (белый) день = в этот день ничего не запланировано** — пробелы в расписании видно
сразу, без прищуривания.

Обновляется само при каждом открытии таблицы, а если вы только что добавили игру и хотите
сразу увидеть её в календаре, не переоткрывая таблицу — **Настолки → Обновить календарь**
в верхнем меню.

Если в один день несколько игр — они объединяются в одной ячейке, каждая с новой строки,
а цвет берётся от первой (по порядку в таблице) игры этого дня.

### Если таблица уже была создана раньше (обновление до жанра/сложности/ссылок/сеттинга/картинки)

Если ваша Google-таблица завелась ещё до того, как появились поля «Жанр», «Сложность»,
«Макс. время игры», «Тесера», «BGG», «Сеттинг» и «Картинка» — таблицу надо один раз вручную
донастроить, я не могу менять её содержимое сама:

1. Откройте лист **Мероприятия**. Колонка **D** называется «Формат» — переименуйте её в
   **«Жанр»** (просто впишите новый текст в ячейку D1). Это чисто косметическое переименование,
   сам код читает эту колонку по позиции, а не по названию, так что ничего не сломается.
2. Допишите 6 новых заголовков в конец строки заголовков: в ячейки **K1, L1, M1, N1, O1, P1**
   впишите соответственно **Сложность**, **Макс. время игры (мин)**, **Тесера**, **BGG**,
   **Сеттинг**, **Картинка**.
3. Заполнять эти 6 колонок для старых строк необязательно — можно оставить пустыми, сайт
   покажет карточку игры просто без этой информации. Заполняйте только для новых игр, если
   хотите показать сложность/время партии/ссылки/сеттинг/картинку на сайте. В «Сеттинг» пишите
   ключевые слова через запятую, например «фэнтези, детектив» — каждое слово станет
   отдельным тегом на карточке. В «Картинка» — просто ссылку на изображение (у него уже должен
   быть свой адрес в интернете, например с Google Диска, Imgur, Tesera/BGG или сайта игры).
4. Обновите код `Code.gs` в Apps Script на актуальную версию из папки сайта (см. раздел
   «Поменять код Code.gs» выше) и **обязательно разверните новую версию** — без этого шага
   новые поля не будут ни читаться, ни записываться.

### Организатор удалил строку в «Мероприятия» — что происходит

Ничего страшного и никаких дополнительных действий не нужно: сайт (и лист «Календарь»)
каждый раз читает таблицу заново, так что удалённая строка просто перестанет показываться
на сайте при следующей загрузке страницы — «место освобождается» само.

Старые записи по этой игре в листе «Записи» никуда не денутся и не помешают — они просто
больше ни на что не влияют, раз самой игры в «Мероприятия» больше нет. Можно даже
анонсировать игру с тем же названием на ту же дату и время заново — система не примет
её за дубликат старой (уже удалённой) строки.

### Кто вообще может добавлять игры и записываться

Сайт устроен «на доверии», без паролей — это осознанный выбор для внутреннего инструмента: любой, у кого есть ссылка на сайт, может записаться на игру (указав имя и почту) или анонсировать новую через `organizer.html`. Если захотите добавить ограничение (например, простой общий пароль для организаторов) — дайте знать, это несложно добавить отдельно.

## Если что-то не работает

- **Сайт открывается, но список игр не грузится / крутится вечная загрузка.** Откройте в браузере ссылку из `config.js` (та, что оканчивается на `/exec`) и допишите к ней `?action=events` — например `https://script.google.com/macros/s/AKfycb.../exec?action=events`. Если видите текст с ошибкой авторизации — вернитесь к шагу 2.7 и проверьте, что «Who has access» стоит «Все» (Anyone). Если видите просто `{"ok":true,"events":[...]}` — значит скрипт работает, дело в чём-то другом (проверьте, что ссылка в `config.js` скопирована без пробелов и опечаток).
- **Записался тестовым именем — а в таблице (лист «Записи») ничего не появилось.** Проверьте, что деплой Apps Script — самый свежий (см. раздел «Поменять код Code.gs», пункт 3): после любого изменения кода нужно разворачивать заново.
- **Даты новых игр, добавленных через организаторскую форму, съезжают на день.** Смотрите шаг 1.8 — часовой пояс таблицы должен быть московским.
- **Организатор пожаловался, что игру нельзя добавить — пишет «уже есть».** Это защита от случайного дублирования: если игра с таким же названием на ту же дату и время уже есть в «Мероприятия», форма её не продублирует. Проверьте лист «Мероприятия» — скорее всего, она там уже есть.
- **Меню «Настолки» не появилось / лист «Календарь» не создался.** Обновите страницу таблицы (F5) ещё раз — иногда меню подгружается с небольшой задержкой. Если и это не помогло, откройте **Расширения → Apps Script**, вручную выберите в выпадающем списке функций (рядом с кнопкой ▶ «Выполнить») функцию `rebuildCalendar` и нажмите ▶ — при первом ручном запуске Google, скорее всего, попросит разрешения (как в шаге 2.8) — разрешите, и дальше меню и автообновление заработают сами.
- **В «Календаре» не хватает игр дальше 16 недель вперёд.** Это настройка `CALENDAR_WEEKS_AHEAD` в самом начале `Code.gs` — поменяйте число на нужное и обновите календарь (менять код — см. раздел выше, но для этой переменной **не** нужно пере-разворачивать веб-приложение, достаточно сохранить и нажать «Настолки → Обновить календарь»).
- **Время на карточке игры выглядит как «1899-12-30t14:59:43.000z» вместо «14:59».** Это известная особенность Google Таблиц: иногда при записи в колонку «Время» значение вроде «14:59» автоматически распознаётся как время и превращается во внутреннее числовое значение, которое отдаётся скрипту как дата 30 декабря 1899 года (служебная точка отсчёта для времени в Таблицах) вместо простого текста. Актуальная версия `Code.gs` уже умеет распознавать и аккуратно переформатировать такие значения обратно в «ЧЧ:ММ» — если видите эту проблему, убедитесь, что в Apps Script развёрнута самая свежая версия кода (см. «Поменять код Code.gs», пункт 3), и обновите страницу сайта.

Если запутались на каком-то шаге — просто напишите мне, на каком именно, и что видите на экране, разберёмся.
