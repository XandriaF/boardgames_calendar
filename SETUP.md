# Как запустить сайт «Настолки билайн» — по шагам, максимально подробно

Ничего заранее уметь не нужно. Просто идите по порядку сверху вниз, ничего не пропуская.

Всего будет 4 шага:

1. Заводим Google-таблицу и вставляем в неё «мозги» сайта (Apps Script).
2. Получаем от Google специальную ссылку.
3. Вписываем эту ссылку в один файл сайта.
4. Выкладываем сайт на Netlify — получаем адрес, который можно всем разослать.

На всё — минут 20, если не отвлекаться.

---

## Шаг 1. Google-таблица

**1.1.** Откройте [sheets.google.com](https://sheets.google.com) под тем Google-аккаунтом, под которым удобно вести таблицу (можно личный, можно рабочий — это не принципиально, но потом с этого же аккаунта нужно будет ставить скрипт).

**1.2.** Нажмите **Пустой файл** (большой плюс / blank spreadsheet) — создастся новая пустая таблица.

**1.3.** Переименуйте её: кликните на «Новая таблица» в левом верхнем углу и впишите, например, «Настолки билайн».

**1.4.** Теперь занесём туда готовую структуру данных, которую я подготовил (файл `Настолки_Билайн_данные.xlsx`):

- В верхнем меню: **Файл → Импорт**.
- Откроется окно. Перейдите на вкладку **Загрузка** и перетащите туда файл `Настолки_Билайн_данные.xlsx` (или нажмите «Выбрать файл на устройстве» и найдите его).
- После загрузки Google спросит, **что делать с импортируемыми данными**. Здесь важно выбрать вариант **«Вставить новые листы»** (Insert new sheet(s)) — НЕ «Заменить таблицу» и НЕ «Заменить текущий лист».
- Нажмите **Импортировать данные**.

**1.5.** Теперь внизу экрана, на вкладках-«ярлычках» листов, у вас должно появиться шесть новых листов: **Инструкция**, **Мероприятия**, **Записи**, **Аккаунты**, **Заявки**, **Заявки_голоса** — вдобавок к пустому «Лист1», который Google создал по умолчанию. Пустой «Лист1» можно смело удалить (правой кнопкой по ярлычку → «Удалить») — он не нужен.

**1.6.** Откройте лист **Мероприятия** и посмотрите на данные — туда уже перенесены игры из вашего старого календаря. Город у всех стоит «Москва» по умолчанию (в старом календаре города не было) — если часть игр в других городах, поправьте вручную прямо в ячейках. Колонка **D** называется «Жанр» (например «Евро, Пати», «Кооперативная» — можно указать несколько через запятую) — тоже необязательная, можно оставить пустой. Колонки **K–P** (Сложность, Макс. время игры, Тесера, BGG, Сеттинг, Картинка) — тоже необязательные, заполняются только если хотите показать эту информацию на сайте. Колонка **Q** («Email организатора») уже обязательна для новых игр, добавленных через форму — заполните её и для старых строк, если хотите, чтобы участники видели почту организатора при наведении. Колонка **R** («Закрытое») — ДА/НЕТ, по умолчанию НЕТ; подробнее в разделе «Закрытые мероприятия» ниже. Колонка **S** («Занято организатором») — число, по умолчанию 0; ей управляет кнопка +/- на сайте (см. «Занять места без имени и почты (+/-)» ниже) — руками её обычно трогать не нужно. Колонка **T** («Тип») — «Игра» или «Событие»; пустая ячейка тоже считается «Игрой» (для старых строк). Колонка **U** («Игры события») — техническая, ей управляет форма анонса, руками трогать не нужно (см. «Настольные игры к «Событию»» ниже). Подробнее про T/U — в разделе «Анонсировать игру или событие» ниже.

**1.7.** Лист **Записи** не трогайте — туда сайт будет сам записывать, кто на что записался. Руками там ничего заполнять не нужно.

**1.7б.** Лист **Аккаунты** тоже не трогайте руками, кроме одной колонки — **D («Роль»)**. Туда сайт сам записывает всех, кто хоть раз указал себя через «это вы» (email, имя, придуманный ими 4-значный код). Единственное, что можно и иногда нужно делать здесь вручную — это назначить кому-то роль **«Амбассадор»** в колонке D (выберите из выпадающего списка в нужной строке, по email). Подробнее — в разделе «Аккаунты, код (PIN) и роль амбассадора» ниже.

**1.7в.** Лист **Заявки** — сюда вы (или амбассадоры) вручную вписываете игры, которые хотите видеть на вкладке «Приём заявок» сайта: колонка A — название игры, B — доступность в офисе/офисах (можно несколько через «;», точку с запятой — запятая внутри описания одного офиса, например «локер 5, 2 этаж», не мешает; оставьте пустым, если пока нигде нет), C — возможность сыграть на BGA, чекбокс да/нет (ставится вручную). Сайт только читает этот список и считает голоса — сам он в него ничего не пишет. Подробнее — в разделе «Приём заявок» ниже.

**1.7г.** Лист **Заявки_голоса** не трогайте — туда сайт сам записывает, кто за какую игру поставил плюсик (и снял его). Руками там ничего заполнять не нужно.

**1.8.** Последняя мелочь, но важная: проверьте часовой пояс таблицы, чтобы даты новых игр не съезжали на день. **Файл → Настройки таблицы** (Settings) → вкладка **Общие** → **Часовой пояс** → должно быть выбрано что-то вроде «(GMT+03:00) Москва». Если нет — выберите московский пояс и нажмите **Сохранить настройки**.

Таблица готова. Теперь вставим в неё скрипт, который умеет отдавать данные сайту и записывать в неё новых участников.

## Шаг 2. Apps Script — «мозги» сайта

Это встроенный в Google Таблицы редактор кода. Пугаться не нужно — просто скопируем готовый код целиком, ничего писать самим не придётся.

**2.1.** В вашей Google-таблице, в верхнем меню: **Расширения (Extensions) → Apps Script**.

**2.2.** Откроется новая вкладка браузера — это редактор кода (script.google.com). Там уже будет файл с названием `Код.gs` или `Code.gs` и внутри — заготовка вида:

```
function myFunction() {

}
```

**2.3.** Кликните внутрь этого окна с кодом, нажмите **Ctrl+A** (выделить всё), затем **Delete** — весь текст должен исчезнуть.

**2.4.** Откройте на своём компьютере файл `Code.gs` из папки с сайтом (можно в Блокноте / любом текстовом редакторе), выделите там всё (**Ctrl+A**), скопируйте (**Ctrl+C**).

**2.5.** Вернитесь в окно Apps Script и вставьте (**Ctrl+V**) — весь код должен появиться в редакторе.

**2.6.** Сохраните: нажмите на иконку дискеты в панели инструментов (или **Ctrl+S**).

**2.7.** Теперь опубликуем это как веб-приложение, чтобы сайт мог с ним общаться:

- Справа сверху — синяя кнопка **Развернуть (Deploy)** → **Новое развёртывание (New deployment)**.
- Рядом с полем «Выберите тип» (Select type) нажмите на иконку ⚙️ (шестерёнку) → выберите **Веб-приложение (Web app)**.
- Появятся поля:
  - **Описание** — можно вписать что угодно, например «настолки билайн», необязательно.
  - **Execute as / Выполнять как** — должно стоять **Я (Me)**.
  - **Who has access / У кого есть доступ** — выберите **Все (Anyone)**. Это нужно, чтобы сайт (который открыт всем) мог получать данные. Если ИБ компании не разрешает вариант «Все» — выберите «Все в организации» (Anyone within [ваша организация]), тогда сайт будет работать только для тех, кто залогинен в корпоративный Google.
- Нажмите **Развернуть (Deploy)**.

**2.8.** Google попросит авторизовать доступ — это нормально, ведь скрипт сейчас будет читать и писать в вашу же таблицу:

- Нажмите **Авторизовать доступ (Authorize access)**.
- Выберите свой Google-аккаунт.
- Может появиться экран **«Google не подтвердил это приложение»** («Google hasn't verified this app») — это нормально и ожидаемо, ведь это ваш собственный только что написанный скрипт, а не чужое приложение. Нажмите мелкую ссылку **Дополнительные настройки (Advanced)** внизу, затем **Перейти на страницу «[название проекта]» (небезопасно)**.
- На следующем экране нажмите **Разрешить (Allow)**.

**2.9.** После этого появится окошко с надписью **«Развёртывание обновлено»** и полем **URL веб-приложения (Web app URL)** — это ссылка вида:

```
https://script.google.com/macros/s/AKfycb.........................../exec
```

Скопируйте её целиком (рядом есть кнопка-иконка «копировать») и сохраните куда-нибудь рядом — она понадобится буквально через минуту. Нажмите **Готово (Done)**.

⚠️ **Важно на будущее:** если вы потом захотите поменять код `Code.gs` (например, что-то в логике), одного сохранения недостаточно — нужно **создать новое развёртывание** (или зайти в «Управление развёртываниями» → нажать на карандаш/редактировать у существующего → в поле «Версия» выбрать «Новая версия» → Развернуть). Иначе изменения не попадут на уже опубликованный URL, и сайт продолжит работать по-старому.

**2.10.** Закройте вкладку с редактором кода и вернитесь к вашей Google-таблице, затем **обновите страницу браузера** (F5). Через пару секунд должно произойти две вещи:

- вверху появится новое меню **«Настолки»** (рядом с «Файл», «Правка» и т.д.);
- автоматически появится (или обновится) лист **«Календарь»** — это тот самый понедельный календарь с цветными ячейками, как в вашем исходном файле, только теперь он собирается сам из листа «Мероприятия» и не может разойтись с сайтом. Пустые дни остаются просто белыми — сразу видно, где в расписании пробел.

Если после обновления страницы Google спросит разрешение ещё раз (это отдельный, более простой запрос, не такой как в 2.8) — нажмите «Разрешить». Дальше календарь будет обновляться сам каждый раз, когда вы открываете таблицу, а если нужно обновить прямо сейчас, не переоткрывая — жмите **Настолки → Обновить календарь**.

## Шаг 3. Вписываем ссылку в сайт

**3.1.** В папке с сайтом найдите файл `config.js`, откройте его в любом текстовом редакторе (Блокнот подойдёт).

**3.2.** Там будет строка вида:

```js
window.APP_CONFIG = {
  APPS_SCRIPT_URL: "ВСТАВЬТЕ_СЮДА_URL_ВЕБ_ПРИЛОЖЕНИЯ"
};
```

**3.3.** Замените текст `ВСТАВЬТЕ_СЮДА_URL_ВЕБ_ПРИЛОЖЕНИЯ` (вместе с кавычками вокруг него — кавычки оставьте, текст внутри замените) на ту ссылку, которую скопировали в шаге 2.9. Должно получиться примерно так:

```js
window.APP_CONFIG = {
  APPS_SCRIPT_URL: "https://script.google.com/macros/s/AKfycb.........................../exec"
};
```

**3.4.** Сохраните файл (**Ctrl+S**), не меняя ни название файла, ни расширение `.js`.

## Шаг 4. Netlify — выкладываем сайт в интернет

Два способа. **Способ А** быстрее для первого раза, но иногда капризничает с перетаскиванием
папки (браузер может не прочитать какой-то файл — про это ниже). **Способ Б** через GitHub
чуть дольше настроить один раз, зато потом обновлять сайт — одно нажатие, без перетаскиваний,
и он не ломается на ровном месте.

### Способ А. Перетащить папку (быстро)

**4.1.** Откройте [netlify.com](https://www.netlify.com) и нажмите **Sign up** (или **Log in**, если уже есть аккаунт). Можно зарегистрироваться через Google/GitHub-аккаунт — так быстрее.

**4.2.** После входа вы попадёте на главную панель (дашборд). Найдите кнопку **Add new site** (обычно справа сверху) → в выпадающем списке выберите **Deploy manually**.

**4.3.** Откроется страница с большой пунктирной областью и надписью типа «Drag and drop your site output folder here». Откройте у себя на компьютере папку с сайтом (ту, где лежат `index.html`, `styles.css`, `app.js`, `config.js`, `organizer.html`, `organizer.js`, `info.html`, `requests.html`, `requests.js`, `netlify.toml`) — и перетащите **саму папку целиком** (не отдельные файлы по одному, а всю папку сразу) в эту область браузера.

⚠️ **Если видите ошибку «Unable to read file ...» (например, про `config.js`)** — почти всегда это значит, что папка лежит в облачной синхронизации (OneDrive / Google Диск / Яндекс Диск) и файл физически не скачан на компьютер, а хранится «только в облаке». Что попробовать:

- Правой кнопкой по папке с сайтом → пункт вроде **«Всегда хранить на этом устройстве»** (OneDrive) или аналог для вашего облачного сервиса → подождать, пока файлы скачаются полностью → попробовать перетащить снова.
- Или скопировать всю папку на Рабочий стол (обычно вне облачной синхронизации) и перетаскивать уже её.
- Или просто перейти к **Способу Б** ниже — он этой проблемы не знает вообще.

**4.4.** Подождите несколько секунд — Netlify загрузит файлы и опубликует сайт. Появится адрес вида:

```
https://random-name-123456.netlify.app
```

Нажмите на эту ссылку — должен открыться ваш сайт с анонсами игр.

**4.5.** (Необязательно, но приятно) Можно сделать адрес более осмысленным: **Site settings → Change site name** → впишите, например, `beeline-nastolki` → адрес станет `https://beeline-nastolki.netlify.app`. Также в настройках можно подключить свой корпоративный домен, если он есть.

**Готово — сайт опубликован.** Эту ссылку и можно рассылать коллегам.

### Способ Б. Через GitHub (надёжнее, удобнее обновлять потом)

**Часть 1 — загружаем файлы на GitHub**

**4.1.** Откройте [github.com](https://github.com) → **Sign up** (если аккаунта нет) или **Sign in**.

**4.2.** В правом верхнем углу нажмите **+** → **New repository**.

**4.3.** Заполните форму:
- **Repository name** — впишите, например, `nastolki-bilain`.
- Оставьте **Private** (по умолчанию) — необязательно, но так безопаснее.
- Поставьте галочку **Add a README file** — так проще будет заливать файлы дальше.
- Нажмите зелёную кнопку **Create repository**.

**4.4.** На странице репозитория нажмите кнопку **Add file** (справа над списком файлов) → **Upload files**.

**4.5.** Откройте на компьютере папку с сайтом, выделите там **все файлы** (кликните на первый файл, потом Ctrl+A) и перетащите это выделение в область на странице GitHub с надписью «Drag files here to add them to your repository». Либо нажмите ссылку **choose your files** и выберите все файлы через диалоговое окно.

**4.6.** Внизу страницы — поле для сообщения о коммите, оставьте как есть или впишите «Первая версия сайта», нажмите зелёную кнопку **Commit changes**.

**4.7.** Убедитесь, что файлы (`index.html`, `styles.css`, `app.js`, `config.js`, `organizer.html`, `organizer.js`, `info.html`, `requests.html`, `requests.js` и остальные) появились в списке файлов репозитория.

**Часть 2 — подключаем Netlify к этому репозиторию**

**4.8.** В Netlify: **Add new site** → в этот раз выберите **Import an existing project** (не «Deploy manually»).

**4.9.** Нажмите **Deploy with GitHub**. Появится окно авторизации GitHub — разрешите Netlify доступ (можно выбрать «только этот репозиторий» в списке).

**4.10.** В списке репозиториев найдите и выберите `nastolki-bilain`.

**4.11.** На экране настроек деплоя:
- **Build command** — оставьте пустым (сотрите, если там что-то есть).
- **Publish directory** — впишите одну точку: `.`
- Нажмите **Deploy** (может называться «Deploy site» / «Deploy nastolki-bilain»).

**4.12.** Через несколько секунд сайт опубликуется по адресу вида `https://random-name.netlify.app` — так же, как в Способе А (шаги 4.4–4.5 про адрес и переименование применимы точно так же).

**Как обновлять сайт дальше (в этом способе — без перетаскиваний в Netlify вообще):**
Откройте нужный файл прямо на GitHub (кликните на его название в репозитории) → нажмите иконку карандаша (**Edit**) справа сверху → внесите правки → внизу **Commit changes**. Netlify сам заметит изменение и выкатит новую версию сайта в течение минуты-двух — обновлять ничего в Netlify руками не нужно.

## Как дальше жить с этим (частые задачи)

### Добавить новую игру

Два способа — оба рабочие, выбирайте удобный:

- **Через сайт (проще):** откройте ссылку «для организаторов» внизу главной страницы сайта (`ваш-сайт.netlify.app/organizer.html`). Первым делом нажмите **«это вы»** и укажите своё имя, корпоративную почту и придумайте 4-значный код (подробнее — в разделе «Аккаунты, код (PIN) и роль амбассадора» ниже) — эта личность будет использована как организатор. Дальше заполните форму: первое поле — «Игра», город выбирается из выпадающего списка (если нужного города нет — выберите «Другой» и впишите его вручную), жанр — отметьте сколько угодно вариантов из плашек (стратегия, абстрактная, контроль территории, кооперативная и так далее). Внизу — необязательные поля «Сложность», «Макс. время игры», «Сеттинг», ссылка на картинку, ссылки на Тесеру/BGG. Кнопка **«Опубликовать сейчас»** делает игру видимой сразу всем и сразу даёт готовый текст для поста в чат. Кнопка **«Запланировать»** сохраняет игру, но не показывает её никому, кроме вас — подробнее в разделе «Опубликовать сейчас или запланировать» ниже. Чекбокс **«Закрытое мероприятие»** — см. отдельный раздел «Закрытые мероприятия» ниже.

### Лист «Календарь» — визуальный вид на 16 недель вперёд

Это тот же понедельный календарь с цветными ячейками, к которому вы привыкли, только теперь

и всегда показывает 16 недель вперёд, начиная с текущей недели.

Цвет ячейки = статус игры (тот же цвет, что был в вашем старом файле, легенда — в самом
верху листа «Календарь»):

- жёлтый — «Набор открыт»
- зелёный — «Набрано»
- красный — «Отменено»
- синий — «Непубличное»
- голубой — «Черновик»
- оранжевый — «Запланировано» (см. раздел «Опубликовать сейчас или запланировать» ниже)

**Пустой (белый) день = в этот день ничего не запланировано** — пробелы в расписании видно
сразу, без прищуривания.

Обновляется само при каждом открытии таблицы, а если вы только что добавили игру и хотите
сразу увидеть её в календаре, не переоткрывая таблицу — **Настолки → Обновить календарь**
в верхнем меню.

Если в один день несколько игр — они объединяются в одной ячейке, каждая с новой строки,

События (колонка T = «Событие») помечаются пометкой «[событие]» тем же образом.

### Картинка сама подтягивается с BGG

Если в форме анонса заполнить ссылку на BGG, но оставить «Ссылку на картинку» пустой — сайт
сам попробует найти и подставить обложку игры с BoardGameGeek. Это происходит на стороне
Apps Script (не в браузере), потому что у API BoardGameGeek нет поддержки CORS и напрямую
из браузера такой запрос браузер бы просто заблокировал.

⚠️ Для этого Apps Script делает внешний запрос в интернет, а не только читает/пишет вашу
таблицу — при следующем развёртывании (после обновления `Code.gs`) Google может попросить
подтвердить **ещё одно** разрешение в дополнение к уже знакомым (шаг 2.8) — что-то вроде
«Подключаться к внешней службе». Это ожидаемо, разрешите — без этого автоподстановка обложки
работать не будет (но всё остальное продолжит работать нормально, просто без неё).

Если у конкретной игры на BGG обложки не нашлось (или ссылка оказалась неверной) —
мероприятие всё равно создастся, просто без картинки, ошибки не будет.

### Организатор удалил строку в «Мероприятия» — что происходит

Ничего страшного и никаких дополнительных действий не нужно: сайт (и лист «Календарь»)
каждый раз читает таблицу заново, так что удалённая строка просто перестанет показываться
на сайте при следующей загрузке страницы — «место освобождается» само.

Старые записи по этой игре в листе «Записи» никуда не денутся и не помешают — они просто
больше ни на что не влияют, раз самой игры в «Мероприятия» больше нет. Можно даже
анонсировать игру с тем же названием на ту же дату и время заново — система не примет
её за дубликат старой (уже удалённой) строки.

### Запись с гостями (+1/+2)

При записи на игру можно указать, что человек придёт не один — поле «С гостями» в форме записи (без гостей / +1 / +2 и так далее, вариант ограничен тем, сколько мест реально осталось). Гости занимают места наравне с самим участником: например, если осталось 2 места и кто-то записывается «+1» — займутся оба оставшихся места. В списке участников на карточке игры это видно как «Имя +N».

Лист «Записи» при этом автоматически получает 8-ю колонку **«Гости»** — она пишется сайтом сама, руками её заполнять не нужно. Если ваша таблица уже существовала до этой функции, дозаполнять ничего не обязательно: новая колонка появится сама при первой же записи с гостем, а можно и заранее подписать ячейку H1 как «Гости» для наглядности.

### Занять места без имени и почты (+/-)

Иногда часть игроков договаривается вне сайта (в чате, лично) и не хочет отдельно
записываться через форму. Для этого на карточке мероприятия — но **только для его
организатора** (когда он зашёл на сайт под своей почтой) — появляется строка «Занято без
записи: N» с кнопками **−** и **+**. Каждый клик по «+» помечает одно место как занятое,
без имени и почты; «−» снимает отметку. Эти места складываются с обычными именными
записями при подсчёте «занято из максимума» — счётчик мест на карточке (например «3 из 5
(свободно: 2)») учитывает и то, и другое сразу.

Если максимум участников задан (колонка H) — «+» не даст занять больше мест, чем есть
на самом деле (сайт покажет ошибку). Если максимум не задан — ограничений нет.

Это число хранится в новой колонке **S («Занято организатором»)** на листе «Мероприятия» —
по умолчанию 0, руками её обычно менять не нужно, только через кнопки на сайте. Обычным
участникам (не организатору) эта строка на карточке вообще не показывается.

### Прошедшие игры спрятаны, «проявить интерес»

Два связанных изменения на главной странице:

- **Прошедшие игры теперь скрыты по умолчанию.** Под списком карточек есть кнопка
  «показать прошедшие» — по нажатию появляются и уже прошедшие мероприятия (с тем же
  значком «Уже прошло», что был и раньше), кнопка меняется на «скрыть прошедшие». Ничего
  в таблице для этого настраивать не нужно — это чисто отображение на сайте.
- **Кнопка «Проявить интерес»** — рядом с «Записаться» (или вместо неё, если мест уже
  нет) теперь есть вторая, менее заметная кнопка для тех, кому конкретная дата/время/место
  не подходят, но кто хотел бы сыграть в эту игру в другой раз. По нажатию — та же короткая
  форма «имя + почта», без выбора гостей. Кнопка не показывается, если человек уже
  записан на этот же слот, и пропадает у прошедших/отменённых мероприятий.

Технически интерес пишется той же строкой в лист «Записи», что и запись/отмена — просто с
отдельным статусом **«Интересуюсь»** в колонке «Статус». Мест это не занимает и на
«Записан/Мест нет» никак не влияет — организатор просто видит на карточке подсказку вида
«🙋 ещё 2 хотят сыграть в другое время», если желающие есть. Никаких новых колонок в
таблице добавлять не нужно.

Чтобы это заработало, нужно обновить `Code.gs` в Apps Script на актуальную версию и
**обязательно развернуть новую версию** (см. раздел «Поменять код Code.gs» выше) —
без этого шага кнопка будет появляться на сайте, но отправка формы будет выдавать ошибку.

### Аккаунты, код (PIN) и роль амбассадора

Раньше «это вы» на сайте было просто именем и почтой без проверки. Теперь при первом
указании себя нужно ещё придумать **4-значный код** — он сохраняется в новом листе
«Аккаунты» и привязывается к этой почте:

- **Первый раз с этой почтой** — можно вписать любой код из 4 цифр, он запомнится.
- **Эта почта уже была на сайте** (кто-то уже указывал себя под ней раньше — пусть даже
  с другим именем, главное совпадение по почте) — сайт попросит ввести тот же код, что и
  в прошлый раз. Неверный код — доступ не даётся, показывается подсказка написать
  амбассадору Дарье (ddkolesnik@beeline.ru), чтобы она посмотрела/сбросила код в таблице.
- Код спрашивается **только один раз**, при этом самом «это вы» — дальше на этом же
  устройстве (в этом браузере) сайт запоминает, что вы уже подтверждены, и не спрашивает
  код повторно при записи на игры, «проявлении интереса» или анонсе новой игры.

Всё это хранится в новом листе **«Аккаунты»** (Email / Имя / PIN / Роль / Дата регистрации).
Сайт сам добавляет и обновляет там строки — руками ничего вписывать не нужно, **кроме**
колонки **«Роль»**.

**Роль «Амбассадор»** — это и есть замена старой кнопки «я — амбассадор» с секретным
словом (её больше нет). Роль можно поставить **только вручную, прямо в таблице**, открыв
лист «Аккаунты», найдя нужную строку по email и выбрав «Амбассадор» в колонке D (по
умолчанию там «Участник» или пусто — это одно и то же). На сайте эту роль нельзя ни
поставить, ни даже увидеть — это осознанно скрыто от обычных пользователей.

Тот, у кого стоит роль «Амбассадор», при заходе на сайт под своей почтой автоматически
видит **все** запланированные (ещё не опубликованные) и **все** закрытые мероприятия всех
организаторов, а не только свои — и может опубликовать любое из них. Удобно, если хотите,
чтобы кто-то один проверял анонсы перед публикацией или помогал с закрытыми встречами.

### Опубликовать сейчас или запланировать

В форме анонса — две кнопки:

- **«Опубликовать сейчас»** — как раньше: игра сразу видна всем на сайте, статус «Набор
  открыт», сразу выдаётся текст для поста в чат.
- **«Запланировать»** — сохраняет игру в таблицу со статусом **«Запланировано»**, но НЕ
  показывает её на сайте никому, кроме вас самих (по почте организатора) и амбассадоров.
  Удобно, если детали ещё не окончательные и рано анонсировать всем. Текста для поста в
  этом случае не будет — вместо этого покажется напоминание, что игру нужно будет
  опубликовать позже.

Чтобы опубликовать запланированную игру: зайдите на главную страницу сайта под той же
почтой, что указывали при создании (кнопка «это вы») — ваша запланированная игра сама
появится в общем списке с оранжевым значком «Запланировано» и кнопкой **«Опубликовать»**
вместо «Записаться». Нажмите её — и игра станет обычной публичной, как будто вы сразу
выбрали «Опубликовать сейчас».

### Закрытые мероприятия

В форме анонса есть чекбокс **«Закрытое мероприятие (запись только через организатора)»**.
Если его отметить:

- появляется предупреждение о том, что другие люди не смогут сами записаться на это
  мероприятие через сайт;
- появляется поле **«Участники закрытого мероприятия»** — впишите туда всех, кого хотите
  сразу записать, по одному человеку на строку, в формате `Имя, почта` (например
  `Иван Иванов, ivan.ivanov@beeline.ru`); если написать только почту без имени — сайт
  сам возьмёт часть до «собаки» как имя.

Такое мероприятие ведёт себя как «Запланировано» с точки зрения видимости: оно **не**
показывается в общем списке на главной странице никому постороннему — только организатору,
амбассадорам и тем, кого вы вписали участниками (они увидят его среди «своих» мероприятий,
когда зайдут на сайт под той же почтой). Кнопка «Записаться» на карточке такого
мероприятия у всех остальных неактивна — добавить нового участника можно только вписав
его почту вручную прямо в лист «Мероприятия»/«Записи» (или пересоздав мероприятие, если
список участников нужно расширить существенно).

В таблице это отмечается колонкой **R («Закрытое»)** на листе «Мероприятия» — ДА/НЕТ.
«Закрытое» — это отдельная, независимая настройка от «Статуса»: закрытое мероприятие
по-прежнему может быть «Набор открыт»/«Набрано»/«Отменено», просто скрыто из общего списка.

### Анонсировать игру или событие

Вверху формы анонса (`organizer.html`) — переключатель из двух кнопок: **«Анонсировать
игру»** (как раньше, по умолчанию) и **«Анонсировать событие»**.

**«Событие»** — это просто отметка на сайте о том, что что-то будет (субботник, встреча
клуба, день рождения офиса и т.п.), без записи и без счётчика мест. При выборе этого
режима форма сама прячет всё, что относится только к играм (жанр, макс. участников,
сложность, макс. время партии, сеттинг, картинка, ссылки на Тесеру/BGG, комментарий,
чекбокс «закрытое») — остаются только: описание (это то же поле, что «Игра», просто
переименованное и с другой подсказкой), дата, время, город и «где». На главной странице
такая карточка получает бейдж **«Событие»** вместо «Идёт запись»/«Мест нет», не показывает
блок участников/резерва мест и кнопку «Проявить интерес» — на неё в принципе нельзя
записаться, это просто информационная метка.

В таблице это хранится в новой колонке **T («Тип»)** на листе «Мероприятия» — значение
«Игра» или «Событие» (пустая ячейка = «Игра», для обратной совместимости со старыми
строками). Если для события всё же попытаться отметить «закрытое» — сайт эту настройку
проигнорирует и всегда снимет её, потому что для события без записи она не имеет смысла.

### Настольные игры к «Событию»

В режиме «Анонсировать событие» под основными полями есть необязательный блок
**«Настольные игры на событии»** с кнопкой **«+ добавить игру»**. У каждой добавленной игры —
те же поля, что и в обычном анонсе игры (название, жанр, сложность, макс. время партии,
сеттинг, ссылки на Тесеру/BGG, картинка), кроме «Макс. участников» — у события нет мест
и записи в принципе, поэтому оно не относится ни к одной конкретной игре из списка. Можно
добавить сколько угодно игр или не добавлять ни одной — это чисто информационная деталь:
покажет участникам, во что можно будет поиграть на событии, но никак не влияет на запись.

На главной странице карточка события со списком игр показывает их названия и жанр/сложность/
ссылки отдельным блоком под описанием. Это хранится в новой технической колонке **U
(«Игры события»)** на листе «Мероприятия» — одна игра на строку внутри ячейки, поля внутри
строки разделены `||` в том же порядке, что и в обычной форме анонса. Формат читаемый и
теоретически правится вручную прямо в таблице, но проще и надёжнее всегда пользоваться
формой на сайте — вручную эту колонку трогать не нужно. Для типа «Игра» колонка U всегда
остаётся пустой (сама игра уже полностью описана обычными полями формы).

### Три вкладки на сайте

Вверху каждой страницы — три вкладки: **«Календарь»** (главная, всё то, что описано выше),
**«Приём заявок»** и **«Важная информация»**. Переход между ними не требует повторного входа —
личность («это вы», сохранённая через имя+почту+код) общая для всех вкладок сразу, в браузере.

### Приём заявок

Вкладка со списком настольных игр, которые сотрудники хотели бы видеть в офисах —
с голосованием плюсиками, в виде таблицы. Список пополняется **только вручную**, в листе
**«Заявки»** (см. шаг 1.7в выше): колонка A — название игры, B — доступность в офисе(ах)
(текстом, можно несколько через «;»), C — возможность сыграть на BGA (чекбокс да/нет),
D — амбассадор(ы), кто может провести (текстом, тоже можно несколько через «;», необязательно).
Сайт (`requests.html`) только показывает этот список и умеет ставить/снимать голос —
добавить новую игру в список через сайт нельзя, это осознанно оставлено ручным процессом
для амбассадоров/организаторов.

На странице есть фильтр по городу (ищет совпадение и в колонке «Доступность в офисе», и
в колонке «Амбассадор(ы)») и сортировка — по популярности (по умолчанию) или по алфавиту
в любую сторону. Оба работают на уже загруженном списке, без повторных обращений к таблице.
На узких экранах (телефон) таблица сама превращается в список карточек.

Голосование: **один плюсик на игру на человека**, но поддержать можно сколько угодно разных
игр — плюсик на «Каркассон» никак не мешает поставить ещё один на «Манчкин». Повторное
нажатие на уже активную кнопку снимает голос. Как и везде на сайте, голосовать может только
человек с подтверждённой личностью («это вы», имя+почта+код) — если она ещё не задана, первое
нажатие на плюсик откроет ту же модалку, что и при записи на игру. По умолчанию список
отсортирован по убыванию числа голосов, чтобы сразу было видно самые желанные игры.

Технически голоса хранятся событийно в листе **«Заявки_голоса»** (см. шаг 1.7г выше) — по
той же схеме, что и «Записи»/сигналы интереса: каждое нажатие пишет новую строку, а
засчитывается только последний статус на пару (игра, email). Руками этот лист трогать не
нужно.

### Важная информация — ссылки на сообщества

Статическая вкладка (`info.html`) со ссылками на чаты/каналы/правила клуба и т.п. — без
какого-либо подключения к таблице, просто список ссылок. Сайт создан с несколькими
**ссылками-заглушками** (`href="#"` или `href="https://t.me/"`) — их нужно один раз заменить
на настоящие: откройте файл `info.html` в любом текстовом редакторе (или на GitHub, если сайт
выложен Способом Б — см. «Поменять что-то на самом сайте» выше) и в каждом блоке
`<a class="info-link" href="...">` впишите свою ссылку и, если нужно, поправьте текст рядом.
Блоков можно добавлять и удалять сколько угодно — просто копируйте один такой блок целиком
и меняйте содержимое.

### Жанр — теперь можно отметить несколько, город — из списка

В форме анонса «Жанр» — это набор плашек (стратегия, евро, америтреш, абстрактная, контроль
территории, кооперативная, пати, карточная, детектив/дедукция, НРИ, приключение, экономика,
семейная, варгейм) — отмечайте сколько угодно, они запишутся в одну ячейку через запятую
(так же, как и раньше работал «Сеттинг»), а на карточке игры каждая отобразится отдельным
тегом. «Город» — выпадающий список фиксированных городов; если нужного города нет в списке,
выберите **«Другой»** — появится поле, куда можно вписать город вручную.

### Заглавные буквы

Имена участников/организаторов, города и названия игр теперь автоматически получают
заглавную первую букву — если кто-то впишет «иван иванов» или «москва», на сайте это
покажется как «Иван иванов» и «Москва». Это работает и при записи через сайт, и при ручном
вводе прямо в таблице (сайт просто аккуратно приводит первую букву к заглавной при каждом
показе, ничего в самой таблице не меняя).

### Кто вообще может добавлять игры и записываться

Сайт по-прежнему устроен «на доверии», без единого общего пароля на вход — это осознанный выбор для внутреннего инструмента: любой, у кого есть ссылка на сайт, может записаться на игру или анонсировать новую через `organizer.html`, указав имя, почту и один раз придумав свой личный 4-значный код (см. «Аккаунты, код (PIN) и роль амбассадора» выше) — код защищает именно от того, что кто-то другой запишется или опубликует что-то от чужого имени, а не ограничивает сам доступ к сайту. Если захотите более строгое ограничение (например, единый общий пароль для входа на весь сайт) — дайте знать, это можно добавить отдельно.

## Если что-то не работает

- **Сайт открывается, но список игр не грузится / крутится вечная загрузка.** Откройте в браузере ссылку из `config.js` (та, что оканчивается на `/exec`) и допишите к ней `?action=events` — например `https://script.google.com/macros/s/AKfycb.../exec?action=events`. Если видите текст с ошибкой авторизации — вернитесь к шагу 2.7 и проверьте, что «Who has access» стоит «Все» (Anyone). Если видите просто `{"ok":true,"events":[...]}` — значит скрипт работает, дело в чём-то другом (проверьте, что ссылка в `config.js` скопирована без пробелов и опечаток).
- **Записался тестовым именем — а в таблице (лист «Записи») ничего не появилось.** Проверьте, что деплой Apps Script — самый свежий (см. раздел «Поменять код Code.gs», пункт 3): после любого изменения кода нужно разворачивать заново.
- **Даты новых игр, добавленных через организаторскую форму, съезжают на день.** Смотрите шаг 1.8 — часовой пояс таблицы должен быть московским.
- **Организатор пожаловался, что игру нельзя добавить — пишет «уже есть».** Это защита от случайного дублирования: если игра с таким же названием на ту же дату и время уже есть в «Мероприятия», форма её не продублирует. Проверьте лист «Мероприятия» — скорее всего, она там уже есть.
- **Меню «Настолки» не появилось / лист «Календарь» не создался.** Обновите страницу таблицы (F5) ещё раз — иногда меню подгружается с небольшой задержкой. Если и это не помогло, откройте **Расширения → Apps Script**, вручную выберите в выпадающем списке функций (рядом с кнопкой ▶ «Выполнить») функцию `rebuildCalendar` и нажмите ▶ — при первом ручном запуске Google, скорее всего, попросит разрешения (как в шаге 2.8) — разрешите, и дальше меню и автообновление заработают сами.
- **В «Календаре» не хватает игр дальше 16 недель вперёд.** Это настройка `CALENDAR_WEEKS_AHEAD` в самом начале `Code.gs` — поменяйте число на нужное и обновите календарь (менять код — см. раздел выше, но для этой переменной **не** нужно пере-разворачивать веб-приложение, достаточно сохранить и нажать «Настолки → Обновить календарь»).
- **Человек говорит, что сайт не принимает его код (PIN) при «это вы».** Скорее всего, эта почта уже была на сайте раньше (например, с другим именем) под другим кодом — он этого не помнит. Откройте лист «Аккаунты», найдите строку с этой почтой и либо подскажите ему записанный там код (колонка C), либо впишите новый код прямо в ячейку (человек должен будет ввести именно то, что там теперь стоит).
- **Нужно назначить кого-то амбассадором.** Лист «Аккаунты» → найдите строку по email (если человек ещё ни разу не заходил на сайт — строки не будет, попросите его сначала один раз пройти «это вы») → в колонке D выберите «Амбассадор». С сайта это не делается нигде и никак — только руками здесь.
- **Время на карточке игры выглядит как «1899-12-30t14:59:43.000z» вместо «14:59».** Это известная особенность Google Таблиц: иногда при записи в колонку «Время» значение вроде «14:59» автоматически распознаётся как время и превращается во внутреннее числовое значение, которое отдаётся скрипту как дата 30 декабря 1899 года (служебная точка отсчёта для времени в Таблицах) вместо простого текста. Актуальная версия `Code.gs` уже умеет распознавать и аккуратно переформатировать такие значения обратно в «ЧЧ:ММ» — если видите эту проблему, убедитесь, что в Apps Script развёрнута самая свежая версия кода (см. «Поменять код Code.gs», пункт 3), и обновите страницу сайта.
- **Вкладка «Приём заявок» пустая / игры не голосуются.** Проверьте, что в таблице есть лист «Заявки» с заголовками «Игра, Доступность в офисе, Возможность сыграть на BGA, Амбассадор(ы), кто может провести» и хотя бы одной игрой ниже (см. шаг 1.7в) — сайт только читает этот лист, сам туда ничего не добавляет. Если список видно, но нажатие на плюсик ничего не делает — проверьте, что деплой Apps Script свежий (см. «Поменять код Code.gs», пункт 3).
- **Вкладки «Приём заявок» / «Важная информация» ведут на пустую страницу или 404.** Файлы `requests.html`, `requests.js`, `info.html` не попали на Netlify вместе с остальными — проверьте, что все три файла лежат в той же папке/репозитории, что и `index.html`, и переопубликуйте сайт (см. «Поменять что-то на самом сайте» выше).

Если запутались на каком-то шаге — просто напишите мне, на каком именно, и что видите на экране, разберёмся.
